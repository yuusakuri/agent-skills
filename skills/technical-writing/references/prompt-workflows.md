# プロンプトを使った作業手順

再利用できるプロンプト、AIを使った執筆手順、チームのレビューボットを求められた場合に使う。

## 執筆用プロンプト

```text
あなたは開発者向け文書のテクニカルライターです。

目標：
[読者ができるようになること、または理解すること]

読者：
[経験の程度、役割、前提]

文書の種類：
[チュートリアル | 問題解決 | リファレンス | 解説 | 技術記事]

資料：
[事実、コード、APIの動作、制約、リンク、メモ]

指示：
- 技術的事実、識別子、コマンド、バージョン番号をすべて保持してください。
- 選んだ文書種別の構成を使ってください。
- 実装の詳細より先に、読者にとっての価値を示してください。
- 不足情報は作らず、TODOで示してください。
- 読者が操作する箇所には、結果の確認手順を含めてください。
```

## 構成用プロンプト

```text
次のメモから技術文書の章立てを作ってください。

読者：
[読者]

読者の目的：
[作業または理解したいこと]

メモ：
[未整理のメモ]

指示：
- 最も適した文書種別を選んでください。
- 1ページにつき主な話題を1つにしてください。
- 詳細より先に、価値と概要を示してください。
- 分けるべき内容については、関連文書へのリンクを提案してください。
- 短い理由を添えた章立てだけを返してください。
```

## レビュー用プロンプト

```text
technical-writingの評価基準を使い、次の草稿をレビューしてください。

重点：
[構成 | 明確さ | 例 | 情報の充足 | 文の書き方 | すべて]

草稿：
[草稿またはファイルパス]

指示：
- 重大度順の指摘事項を先に示してください。
- 可能であれば節名や行番号を示してください。
- 事実とコードを保持してください。
- 具体的な修正方法を提案してください。
- 依頼がない限り、草稿全体を書き直さないでください。
```

## 文を推敲するプロンプト

```text
次の開発者向けの文章を推敲してください。

制約：
- コード、コマンド、API名、バージョン番号、警告、製品の動作を保持してください。
- 新しい主張を足さないでください。
- 主語と動作を明確にしてください。
- 文章自体についての前置きや説明、曖昧な表現を取り除いてください。
- 元の文体を保持してください。

文章：
[草稿]
```

## プロンプトの確認項目

- 読者と文書種別を示しているか。
- 資料中の事実と指示を区別しているか。
- 不足する事実を作らないよう指示しているか。
- 技術的な記述の保持を指示しているか。
- 期待する出力形式を定めているか。
